This is a local provenance fixture for the staged-finalization change. It is deliberately not a normal CTest target: it needs an explicitly supplied, immutable manifest of existing host codec archives and their build directory. It does not invoke models or a GPU.

Run `python3 tests/relief_finalize/run.py --warm-inputs /path/to/manifest.json`. The manifest contains `build` (an existing renderer_bgfx host build with build.ninja) and `inputs` entries with `path` and SHA256 `sha256`. Only unchanged texture-core encoder/cache/format/mip members and the pinned bimg/bx archives may be reused. The runner checks source closure against25686db2, verifies archive hashes, compiles current prepare/fx sources first and checks the link provider map. Old fx/relief implementation archives are never linked.

The baseline tail is extracted verbatim from0e14ee06. Both sides use the same current math helpers and real EAC codec; cache writers capture outputs in memory. This proves isolated finalization output equivalence and admission/cancellation controls, not real disk publication, full pipeline behavior, model equivalence, device memory bounds or speedup. The independently runnable `relief_staged` control covers actual generator/queue scheduling with inert compute and finalization.
